# 接触与合爪审计：结论和实施决策

2026-09-19。范围：稳定到达正确接触位置并合爪。论文仍研究任务级 harness；
不开展新抓取算法研究，不推进 lift/bring_in，不展开无关缺陷。
本轮只读源码/已有记录并更新文档；没有运行仿真、查询或修改活动规划场景、修改控制代码。

## 结论

已有成功证明当前机构存在可行抓取，但尚未证明自主抓取稳定。
首要修改不是新观察求解器，也不是更多姿态搜索：应让规划与接近使用能表达夹爪空隙、
接口周围真实空间和预期接触的同一几何依据，并让合爪以接触条件成立为前提。
现有粗障碍模型加多套目标排除规则，不能继续承担精细接触可执行性的判断。

## 源码确认的共同问题

1. **机器人模型把夹持空隙填成实体。**
   `openral/packages/rm_75_config/config/lunarbot_body.xacro` 中 eg2_gripper 是一个
   92×30×143 mm 实心盒，固定在 Link7；TCP 位于 Link7 的 z=140 mm。
   该模型适合粗略包络，但不能判断细颈进入两指间是否允许。
   例如参考闭合的把手中心在 TCP 约 [0.3,4.7,-10.6] mm，换算 Link7 为
   [0.3,4.7,129.4] mm，位于这个实心盒内部。这是模型与接触任务的结构性冲突。
   它不证明报告的 48.8 mm 穿透完全来自这个盒子，环境模型也参与碰撞。
2. **环境模型填掉悬空结构下方的空间。**
   `openral_ext/planning_scene/node.py::columns` 把每个 80 mm 水平单元从估计地面
   填到最高测量点；T 头下面的空间因此不能被真实表达。
   `minus_the_job` 先删除球内点、再生成柱体，球外的高点仍可能生成穿过球内的柱体。
   因而“排除了点”也不等于“规划模型排除了相同体积”。不能靠继续放大排除半径修复。
3. **规划与伺服的允许空间不同。**
   MoveIt 使用上述柱体和 105 mm 球形排除；pick 的 guard 使用 50 mm 高度图、
   BODY_POINTS、近邻半径和 item_cells 连通区域排除。servo_twist 只调用这个局部 guard，
   并未走另一个 servo 中的逐步 MoveIt 状态有效性检查；独立低层安全仍存在。
   这不是重复保险：两套表示可能分别拒绝正确抓取、放行错误接近。
4. **操作声明不是规划场景更新确认。**
   working_on 发布 topic 后立刻调用 IK；场景节点每 1 仿真秒重建一次，再异步发布给 MoveIt。
   没有确认本次接触声明已经应用。声明两秒到期，搜索中也不续期。
   但 g8i approach=127.60、结束=127.64 仿真秒，不能把本次失败归因于两秒过期；
   尚未记录每次 IK 所见场景，因此更新竞态是明确的设计缺口、不是已证实的唯一根因。
5. **接近结束没有独立的接触到位判据。**
   close-in 捕获可局部重试的 StageFailure，只要 TCP 到接触点的距离不超过
   close_in_short_ok_m + pad_offset_m（当前合计 32 mm）就可继续；未复核姿态误差。
   grasp 随即闭合，只以非空爪角判断是否夹到东西。实际碰到哪一部位并未因此得到证明。
   当前 g8i 没到此分支；它是稳定合爪必须同时收敛的已存在路径，不能留待下一次撞出来。

## 实施方案：一个边界修正，加一个合爪条件

### A. 共享的接触可执行性依据

- 从当前机器人资产/标定导出夹爪掌部、手指和真实开口的碰撞几何，替换实心总包络。
  使用实际张爪状态；闭合过程也必须有对应几何，不能把开爪模型用于所有状态。
  不凭 Mission B 接触点调模型尺寸，不先重建整个机器人描述。
- 仅在接近所需的局部范围，以已有 RGB-D 三维观测表达表面和已观测自由空间，
  替代从地面填高的接触区域柱体。粗场景仍可用于远离接触的规划，但不能重复覆盖局部自由空间。
  未观测区域保留未知，不把“没有深度点”当作可通行。
  实施先复用已安装的几何/碰撞组件，不另造全场景重建或 NBV 系统。
- 同一接触记录关联：选定区域、测量来源与时间、坐标系、接触姿态、合法对称解、
  允许接触的区域及对应手指。目标其他表面、掌部、手臂和邻近物体仍参与碰撞检查。
  不使用“整个目标不是障碍物”的删除规则或全局碰撞豁免。
- 在共享执行/场景接口完成更新确认，再用该上下文做 IK、路径和接近检查。
  确认必须指向消费者实际应用的场景；仅收到 topic 或固定 sleep 均不成立。
  有效期随操作生命周期维护，结束清理；不建立完整并发控制权框架。
- 接近路径使用同一几何与接触许可；复用现有规划/状态检查组件。
  端点 IK 通过不是路径通过。旧局部高度图排除不再作为精细接触的另一套授权依据。

### B. 合爪只能发生在接触条件成立后

- 保留 RGB-D 接触轴修正和目标承诺；保留合法对称姿态，但选定后不翻转或倾斜换解。
- 显式核对实际 TCP 的位置、方向、手指进入关系及目标证据是否仍有效。
  几何条件来自夹爪/接口和现有控制精度；若现有证据不足以证明插入深度，返回缺口，
  不用前表面加半宽的近似冒充已测量深度，也不增设任意误差阈值。
- 删除 close-in 停滞后按宽松距离直接合爪的成功路径。
  合爪后记录非空接触及其证据；不提起、不收臂、不把非空爪直接写成 held。

### C. harness 的最小增强

复用已有阶段反馈、最终 evidence 和权威事实通路，不新增研究级框架。
反馈至少区分：接触几何缺证据、场景尚未就绪、具体碰撞、IK 未找到解、
接近未到位、目标证据失效、合爪接触未确认。保留原始错误、接触/场景引用和实际物理状态。
IK 失败不能一律宣称物理不可达，更不能驱动模型无依据地挪动底盘。
共享能力负责测量与可执行性；harness 保存证据和矛盾、维持未知事实，reasoner 决定
补观察、重定位或换能力。服务故障不伪装成语义恢复问题；无新证据不算失败条件已解除。
这些结果同样提供给基线；不在 harness 写 Mission B 恢复序列。

## 有限验证与停止扩张条件

1. 离线使用历史成功姿态和对应观测，验证模型表达真实夹爪空隙及进入空间；
   同时对照 g8h 真实提前碰撞，避免把修复做成一律放行。真值仅用于评价。
2. 在实现中确认更新已应用，并让 IK、路径和接近记录引用同一操作上下文；
   不需要重演所有旧事故。g8i 的精确逐次场景未录到，不无限追溯重建。
3. 上述依据一致后，只做接触诊断：从现有张爪快照出发，选中细颈、正确到位、合爪后停止。
   判别实际接触关系、是否提前推动物体、闭合前条件是否成立；不以“没有报错”作为通过。
4. 单次通过后，用已有另一张爪起始姿态检查复现性，再报告证据覆盖范围；
   不将有限开发复现写成稳定性统计，更不写成 Mission B 成功。

不展开：完整 C1 主动观察求解器、完整 C3 抢占、Mission A 联合站位、place/stow/dock、
所有 VLM 误判、全场景稠密重建、更多摩擦调参、追查每次旧滑落的完整力学原因。
已授权的夹爪材质保持不变；现阶段不能声称它改善了抓持。
如局部三维表示缺少必要观测，针对进入通道复用现有观察能力补证据；只有实测证明
现有能力无法取得该证据，才重新评估观察实现，不能据此提前扩大工程范围。


## 实施记录（2026-09-19）

已落地：真实关节驱动的夹爪碰撞网格、局部观测表面、MoveIt 场景应用确认、
带实际夹爪状态的 IK/全机器人有效性查询、接近逐步同源检查、观察自由射线证据、
取消宽松合爪兜底，以及 harness 上下文保存具体执行条件。
深度无回波语义由实际相机配置经传感器桥提供，不在 skill 中猜测 inf 的含义。

历史成功姿态在旧模型被实心夹爪包络拒绝，在新模型/观测场景中通过 IK 和状态检查；
已有提前碰撞记录中的一个姿态仍被真实掌部碰撞拒绝。两者不是对全部历史运行的重演。
g8m 已实际到位合爪，照片及真值评价显示正确接触；旧未清理检查进程污染了其合爪后记录，
因此不作为静态保持验证。启动脚本已将检查客户端纳入 graph 生命周期。
g8n 复测进一步暴露单点可见性先裁掉对称姿态的问题；现已移除该裁剪，另一姿态
在同一接触的只读 IK/碰撞/观测检查中通过。g8o 实测通过端点与通道检查，
但在最终接近时因 eg2_link6 与观测表面交叠停住（距目标 13 mm），保持张爪、未推动物体。
稳定接触合爪仍未完成；下一步定位该实际路径碰撞，不放宽碰撞阈值。

验证边界必须保留：合爪前条件目前验证选定接触的实际 TCP 到位和锁定状态；
候选中心沿深度仍使用原有“前表面加半宽”的形状估计，不能称为独立测得物体厚度。
自由空间检查是按夹爪网格顶点和既有最小特征步长采样，不能称为连续体积完备证明。
允许手指接触区域的完整表示、持物附着模型和动态场景仍未完成；当前验证到合爪为止。
这些限制应随执行证据解释，不用单次接触结果宣称适用于任意形状或完整 Mission B。
