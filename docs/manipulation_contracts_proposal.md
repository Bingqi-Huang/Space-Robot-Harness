## 1. 设计结论及适用范围

采用“语义操作接口知识 → 有目的的观察 → 接触目标承诺 → 局部闭环执行 → 效果验证”。
观察与抓取是可组合的完整操作；候选生成、跟踪、控制和夹爪闭合仍是内部实现，不拆成模型逐步操纵的工具。
模型可以直接请求 pick；若当前证据满足契约，可以立即执行，无须固定先调用观察。
如果缺少观察证据，pick 返回具体缺口，由模型选择下一步。harness 不写入固定观察—抓取恢复树。

本设计适用于能从机器人传感器辨认操作部位、具备所需控制与验证手段的对象。
“通用”指接口、控制和协调机制不依赖 Mission B 名称、坐标或成功轨迹，不表示支持任意物体。
不支持的接口、不可观测的接触关系或不足的传感器能力必须明确返回，不用场景特例补足。

核心不变量：

- 观察到位不等于看清部位；看清部位不等于可以执行抓取。
- 固定的是对象、接触区域和抓取意图；测量值随同一目标的观测持续更新。
- 任何能力都不能把重新选目标、完整重新观察或改变底盘位置隐藏成局部伺服。
- 旧执行未停止并交接控制权前，不得启动冲突的新动作；取消不会自动松开夹爪。
- 技能报告完成不直接产生权威的 held/placed 事实。

## 2. 知识、证据与职责

### 2.1 操作接口描述

使用可查询、有来源和版本的接口描述，而非在 pick 中按对象名称分支。描述可包含：

| 字段 | 内容与边界 |
|---|---|
| identity / applicability | 接口类别、适用设备记录、来源与版本；当前对象是否匹配仍需观察 |
| contact_semantics | 可接触部位、不可接触部位、接触区域之间的关系 |
| observation_requirements | 为确认操作而必须看清的部位、边界和通道 |
| engagement_constraints | 手指相对接触面的进入方向、夹持关系、退出条件 |
| geometry_prior | 若确有设备文档，可记录带来源的尺寸/公差；未知则留空，不能从仿真真值暗中填入 |
| sensing_requirements | 哪些量必须可测，缺少哪些测量就不支持该操作 |

T 型接口只是一个实例：观察横杆下方颈部及两侧空间，夹持颈部；是否需要横杆限位、插入多深，
必须来自实际接口规格或可辨识几何，不能因为图像像 T 就假定成立。侧向近水平观察是候选策略，
不是所有实例必须满足的姿态，更不能写入某个绝对高度。

区分三类记录：设备知识（持久、带来源）、当前观测（带时间和坐标系）、已核实效果（带验证证据）。
设备知识不能替代实时定位；矛盾时记录 knowledge_mismatch，由模型决定如何处理，不强行把图像拟合成先验。
所有基线获得相同的设备知识、能力和原始机器人证据；Ours 的推理与权威事实机制不共享给基线。
操作内部的 VLM 部位识别/观察评价也属于共享感知能力：所有方法可调用相同服务、版本和输入协议，
并获得相同类型的结果。Ours reasoner 用这些结果决定下一次观察属于方法自身，不在共享技能里
另藏一个决定恢复策略的模型。记录共享感知调用成本，不能将其只计入 Ours 的任务推理。

## 3. 契约 C1：观察成功的定义

### 3.1 接口与前置条件

建议扩展现有 look_at 的语义，而不是新增重复执行基础设施。下列是逻辑字段，不是最终 ROS schema：

```text
look_at(target_ref, interface_ref?, observation_requirement, evidence_ref?)
  -> observation_result
```

observation_requirement 表达“需要看清什么以支持什么操作”；模型不提交相机空间坐标。
请求不是无法执行的任意自然语言：包含 purpose、part_ref、required_relations 和可选的
view_preference，另附自然语言解释。part_ref 来自设备资料或当前图像识别；required_relations
只能使用能力注册表声明支持的语义关系，例如“接触区域可辨认”“两侧通道可测”。
无法解释或缺少实现支持时返回 unsupported_requirement，不用默认观察姿态掩盖。
关系到可见性、投影、间隙的几何求解属于共享观测能力；harness 只校验字段，不编写视角规则。
target_ref 需要有当前粗定位或可用于定向的场景证据；没有时返回 target_unlocalized，
不能仅凭物体名称生成机械臂位置。只读知识查询可以补足接口资料，但不能补足当前位置。
对象尚未定位时，模型可以调用已有相机的只读观察或基于已知设施区域的合法定向能力获取粗证据。
若现有能力无法获得初始证据，应报告能力缺口；不在 harness 中植入“先去某个固定姿态”的规则。
执行前需具备相机标定、图像时间戳与对应机器人状态、运动控制权限和可用的环境几何信息。

### 3.2 从语义到姿态

1. 将请求关联到图像中的对象/部位和已声明的接口约束，保留关联证据。
2. 从当前几何生成候选观察姿态，使用真实 camera↔tool 标定；不把工具轴当作光轴。
3. 检查视场、遮挡、深度可测性、观察姿态的 IK 和运动路径；后续接近可行性用于预测与排序，
   不要求观察前已经知道精确接触位置。未知空间不当作已证实空闲，也不要求重建整个场景：
   只须覆盖当前运动的扫掠体积及误差裕量；覆盖不足就报告证据缺口。
4. 在满足约束的候选中优先保持姿态连续、减少关节运动；相机正立是偏好，不能凌驾于可达性。
   用当前构型评价连续性；求解器可用多种 seed，但不能只因固定 READY seed 得解就选取大幅绕行路径。
   几何对称解在执行前选定，不能途中翻转。
5. 执行一个选定观察姿态并采集同步证据。可做保持同一观察意图的小幅闭环构图修正；
   到位后语义检查失败或需要改变观察方向/遮挡关系时，返回结果，不隐式遍历固定视角列表。

候选的计算搜索可以有多个解；机器人实际移动到多个不同观察位属于外显的观察行动。
具体求解器和代价参数在实施前复用检查后确定；本设计不把新的 NBV 网络或 MTC 依赖作为前提。

### 3.3 结果与成功判据

```text
observation_result:
  operation_id, target_ref, interface_ref, evidence_id
  pose_reached: satisfied | unsatisfied | unknown
  semantic_visibility: satisfied | unsatisfied | unknown
  geometric_observability: satisfied | unsatisfied | unknown
  approach_feasibility: satisfied | unsatisfied | unknown
  assessment_reason, missing_requirements, measurements, evidence_refs
  satisfied_requirements, downstream_constraints
```

| 判据 | 证据与判断者 |
|---|---|
| pose_reached | 实际机器人/相机状态及运动跟踪误差；运动模块判断，不能只看规划成功 |
| semantic_visibility | 原图、部位标注及 VLM 判断；明确对象与接触区域，不能只写“看到了 T” |
| geometric_observability | RGB-D 与标定下接触相关的位置、方向、间隙及其不确定性；几何模块判断 |
| approach_feasibility | 对已有候选的附加预测；标明候选、检查范围和未知量，可为 unknown；不是观察成功的门槛 |

若请求是“为抓取建立可用观察”，相机到位、语义可见以及请求所需几何可测即满足观察要求。
具体抓取候选及其路径由 C2 建立前检查：**观察成功不蕴含抓取可执行**。
这样避免“先有完整抓取路径才能观察，先观察才能求抓取路径”的循环依赖。
approach_feasibility 可提示后续限制，但其 unknown/unsatisfied 不抹去已成功获得的观察。
若只是身份检查，则按该请求所需的判据判断，不能要求所有 observe 都满足抓取条件。
观测证据仍可部分有效；例如身份已确认而深度不足，不应把所有结果丢弃为一个 false。

失败原因至少能区分 target_unlocalized、view_unreachable、interface_occluded、
knowledge_mismatch、depth_unreliable、geometry_ambiguous、unsupported_requirement。
approach_unverified 作为下游限制返回，不能独自把成功观察判成失败。
结果说明缺少什么，不指定必须调用哪个恢复工具。

### 3.4 有效期

evidence_id 是不可变观测记录，包含图像/深度、CameraInfo、时刻对应 TF/关节状态及评估来源。
可执行性是派生状态，会因对象/底盘/机械臂运动、跟踪断裂、标定或场景变化而失效。
pick 使用前必须重新验证相关条件；同一对象名称或很短的时间间隔都不能自动证明有效。
旧图可用于解释历史，不能自动成为新动作的当前几何。时效容限来自传感器和控制误差预算。

## 4. 契约 C2：接触目标锁定、更新与失效

### 4.1 承诺内容

pick 内部建立 TargetLock，不单独暴露 lock/servo/close 为模型工具：

```text
TargetLock:
  lock_id, generation, target_ref, interface_ref, observation_ref
  committed_contact_region, grasp_relation, approach_branch
  estimate_revision, observed_at, frame_id
  feature_associations, relative_geometry, uncertainty, evidence_refs
  state: valid | degraded | invalid | consumed
```

不可静默改变：对象、接触区域、夹持关系、选定的接近分支。
可持续更新：同一接触区域的位置/方向估计、像素、关联特征及不确定性。
允许在有身份连续性证据的同一区域补充特征；禁止新候选替换旧目标后沿用 lock_id。
若必须重新承诺目标，由下一次执行产生新的 lock_id，历史可关联但不可覆盖。

### 4.2 建立条件

C1 的当前相关证据有效（不要求必须来自一次 look_at 调用）；语义选择与几何候选指向同一部位；接触相关自由度可观测；
夹爪开口、手指扫掠体积与所估计间隙兼容；存在可执行接近段。
不强求对称物体的所有六个自由度都唯一可测，但操作所需的自由度不能含糊。
只有单个像素深度而没有接触关系、方向和通道证据时，不构成完整抓取锁定。
建立锁定前允许在内存中评估多个候选、比较路径；不移动机器人去逐个试抓。
此处求解接近通道、夹持姿态和 §4.5 定义的提起/保持后置条件，并记录所选解。
无解时返回 grasp_infeasible，不将已有效的 C1 证据重标成“观察失败”。

锁定状态转移：新锁定只能在建立条件满足后进入 valid；测量退化进入 degraded；
在同一身份及误差界仍成立的情况下，测量恢复允许 degraded → valid，不调用模型重选目标。
identity 丢失或误差界失效进入 invalid，当前锁定不再恢复为 valid；结束执行后需新锁定。
完成闭合/提起并转为持物监测后进入 consumed；此后维护物体与夹爪关系，不再使用抓取前目标误差驱动运动。

### 4.3 伺服约定

控制器使用同一锁定目标的当前估计及机器人反馈。视觉误差和/或相对位姿误差驱动闭环；
具体采用现有控制路径的哪种表达由标定和离线误差分析决定，不在此声称 IBVS/PBVS 的全局收敛。
位置和旋转误差分别按具名误差预算判定，不直接混合单位构造任意成功阈值。
坐标系变换允许在内部进行，包括短时机器人参考系估计；不能将它写成永久的世界真值。

执行期间保持接近方向/姿态分支连续，检查目标关联、测量新鲜度、误差进展、运动限制与接近通道。
预算和限值来自机器人规格、标定、接口公差或独立开发数据，记录来源；不能根据 Mission B 成败手调。
到达是误差与相关约束同时满足；超时、无进展或限制触发不是“再换个姿态试试”的授权。

### 4.4 丢深度与手指遮挡

| 情形 | 允许行为 | 不允许行为 |
|---|---|---|
| 仍有可靠关联和所需几何 | 继续更新同一锁定并闭环 | 重跑候选选择 |
| 关联存在但深度退化 | 标记 degraded；暂停依赖缺失量的运动。经验证的估计器可作有误差界的短时预测 | 把预测距离伪装成测量，沿视线无限接近 |
| 预期的近接手指遮挡 | 仅在预先验证的末段接触模式下继续，显式报告模式变化 | 把普通跟踪丢失自动解释为可盲插 |
| 身份不确定、误差界超限或目标运动无法解释 | invalid，停止推进并按 C3 交接 | 换点继续、自动全扫描或无证据原地重试 |

末段接触模式需要：最后可靠相对几何及误差界、剩余运动范围、手指/环境通道、
可用的接触或到位停止判据，以及验证过的对象运动假设。没有这些条件就返回 terminal_observability_insufficient。
“插到底”必须转译为可测的接触关系，不能默认平台有力传感器，也不能只以夹爪命令完成作为接触证据。
首个实施版本不承诺支持无视觉末段；离线证据必须先判断该能力是否必要且可实现。

### 4.5 结束与持物语义

到达接触位置、闭合、提起、持物核实是不同事实。报告实际夹爪状态、目标相关视觉证据、
机器人运动及目标与支撑关系；持物判据必须关联目标，不能只跟踪夹爪自身像素。
Ours 的验证器不依赖 skill.success；但共享传感器可能导致共同失效，不能宣称传感器完全独立。
证据冲突或不足时 held=unknown，不猜 true/false。后续运动必须遵守不确定持物状态下的物理限制。

本提案明确 pick 的后置条件：物体已从原支撑分离、处于可停止并维持的持物状态，
并返回证明或否定这些条件的原始证据。提起/脱离量从支撑几何及误差预算求得，不固定写成某个高度。
pick 不默认执行面向导航的内收，也不把“held”解释成“任意姿态都能 carry”。
共享运动层根据实际持物几何和机器人限制判断后续导航是否可执行；若姿态不允许，应返回限制，
由模型调用具备保留持物语义的现有姿态能力。若该能力缺失，列为明确实施缺口，不能复用会开爪的 arm_ready。
本轮不创建新工具、不声称已有安全运输姿态能力；后续实施前须落实复用或最小扩展方案。

最终 outcome 和物理效果分开：即使 pick 返回 failed/canceled，物体也可能已经夹住或脱离原支撑。
harness 对所有可能改变接触/持物的结束路径进行证据核实，不能只在 completed 时验证。
验证默认读取已有动作证据和被动新观测；需要额外提起/晃动等物理试验时不能藏在只读验证器里，
应属于已声明的技能执行阶段，或由模型选择另一个受权限约束的操作。

## 5. 契约 C3：反馈、停止与决策权交接

### 5.1 两种反馈与一个最终结果

```text
OperationEvent:
  operation_id, seq, simulation_time, phase, event_kind
  target_ref, lock_ref?, evidence_refs
  measurements, reason_code?, violated_requirement?
  motion_state, gripper_state, holding_assessment, control_owner

OperationResult:
  outcome: completed | blocked | failed | canceled
  final_phase, reason_code, evidence_refs, physical_state
  stop_ack, ownership_state, final_seq, phase_summary
```

progress 事件记录真实阶段/可测进展，不以 elapsed/deadline 冒充完成百分比。
decision_required 事件解释阻塞及证据，可以在停止过程中发出，但不授权新运动。
blocked 是领域结果：当前执行需要新任务决策；不是 ROS 自带状态。
建议 completed 映射 SUCCEEDED，blocked/failed 映射 ABORTED，外部取消完成映射 CANCELED；
所有映射保留领域原因和物理状态，不能只返回 success=false。

事件路径：skill/perception → OpenRAL runner → capability boundary → harness 事件队列 →
持久记录/上下文。回调只收集和入队，不在回调线程递归调用模型或另一个运动 action。
高频原始控制数据保留本地证据；只把阶段变化、实质退化与终止事件送入任务上下文。
每条都按操作 ID 和序号归属；迟到反馈保留历史但不能覆盖新操作的当前状态。
最终结果包含阶段摘要、最后事件序号和证据引用，不能把关键失败信息只放在瞬时 feedback 中。
权威状态由可核对的结果/观测建立，不能依赖客户端恰好收到所有进展消息。
从未接受或从未取得执行权限的请求明确记录未执行，不伪造物理 stop_ack；只有实际占用过执行资源的
调用需要停止/保持交接。请求被拒绝也不说明之前的其他操作已经停止。

### 5.2 控制权交接顺序

1. 执行器发现本地停止条件，或收到外部取消请求。
2. 共享执行/控制层禁止旧操作继续提交运动目标，并将停稳/保持责任交给具名的控制者；
   在交接过程中保持必要的夹爪/关节输出，不能先杀掉唯一的保持命令源。
3. 请求 worker 协作退出并撤销其命令权限；取消/结束其未完成的规划和控制请求。
   对规划器返回的旧结果也禁止重新下发；等待线程不是防止继续运动的唯一措施。
4. 控制层依据实际反馈确认停止/保持，核实旧命令源已失效、下游请求已处理；
   夹爪持物或持物未知时，不得把取消统一实现为张开夹爪或断开伺服。
5. 记录 stop_ack（旧操作已静默、实际运动已满足停止条件、保持控制者已接管的证据），
   允许后续兼容操作通过同一仲裁入口接管。
6. 返回最终结果；harness 更新证据和事实，由 reasoner 决定下一次操作。

保持控制仍可发必要控制命令；“旧操作停止”表示旧操作不再有发令权，不表示所有电机必须零输出。
若无法确认停止，报告 stop_unconfirmed 并保持冲突动作不可用。具体停止、保持及资源恶化后的
安全处理路径必须先核查当前 controller/runner/safety 是否实际实现；不能以“交给 FDIR”代替设计。
必要机制缺失时是共享执行层的实施阻塞项，不得声称 C3 已满足，也不能直接进入有载荷运行。
这一条件是执行不变量，不是人工审批或任务恢复树。

ROS 的取消接受只表示进入 CANCELING，不能据此认为运动已停。ROS 终态本身也需要应用层
stop_ack 与物理状态证据支撑；所有终止路径（成功、内部失败、异常、外部取消）都遵守同一交接规则。
异常结果不能丢失已获得的阶段和证据，也不能因异常跳过 worker 退出。

### 5.3 调度与恢复

本设计选择“结束当前物理调用、保留未完成的任务目标”，不选择长期挂起 pick 等模型回复后嵌套恢复。
Reasoner 可在停止期间阅读证据；冲突运动只能在交接确认后提交。安全停止不等待模型或远端 VLM。
同一机械臂/夹爪的命令源必须唯一；与底盘有关的冲突按共享物理约束仲裁，不笼统禁止持物导航。
只读查询可在资源允许时并行。实施时复用 runner/safety 的现有仲裁机制，缺失部分才做最小扩展。

下一次 pick 可以引用原观察以保留语义背景，但必须验证新鲜度并建立当前锁定。
“resume”不是恢复旧 worker 或旧坐标。遇到持物未知时，不允许用“重新 pick”隐式开爪重置。
模型没有及时回复时停留在已验证的本地保持/安全状态；受物理资源限制的处理遵守已核查的安全机制。
物理所有权约束由共享执行层强制，Ours harness 镜像其状态；不能仅凭 Ours 的 Python 调用顺序保证互斥。
事件队列和本地停止持续运行；首版在最终结果后触发下一次任务推理，不要求并行运行第二个 reasoner。
decision_required 是信息与停止意图，只有交接完成才允许新运动；外部人工/安全取消不等待任务推理。
重试预算是显式配置与任务资源，不在 harness 中写“失败两次就换工具”。

## 6. 一条完整交互示例（解释机制，不进入任务提示词）

```text
Reasoner → pick(target, interface)
pick → blocked(observation_insufficient), stop_ack
Harness → 记录缺少接触部位证据，任务目标仍未完成
Reasoner → 查询接口资料，选择 look_at 的观察要求
look_at → pose_reached=true, semantic_visibility=false，附遮挡图像；停止并返回
Reasoner → 根据证据修改观察要求（也可选择其他能力）
look_at → 所需判据满足，返回 observation_ref
Reasoner → pick(target, interface, observation_ref)
pick → lock_created → approaching（同一锁定持续更新）
    成功：接触/闭合/提起证据 → completed → harness 独立核实持物
    受阻：path_blocked → stopping → stop_ack → blocked → reasoner 决定下一步
```

前半段不是强制序列：已有有效观察时可直接 pick；图像证据不足时也可以放弃或改任务。
成功路径的控制阶段是通用物理操作程序；跨操作的观察选择和恢复仍是模型策略。

## 7. 文献依据、替代方案与论证限度

以下将文献事实与本项目的设计选择分开；文献不证明我们的实现必然成功。

| 来源 | 支持的事实/思想 | 本项目推论与限制 |
|---|---|---|
| [R1] Affordance Templates | 对象操作知识可关联感知表示和操作 | 借鉴接口描述；不照搬人工注册、任务路点或固定恢复流程 |
| [R2] Closed-Loop Next-Best-View | 可根据遮挡与抓取信息在线选择继续观察或执行 | 借鉴任务驱动观察；不引入完整学习/重建栈，也不声称其性能可转移 |
| [R3] Visual Servo Control 教程 | 视觉反馈控制区分图像/位姿误差，存在稳定性、可达性和特征丢失问题 | 锁定目标而更新估计；不承诺全局或 100% 收敛 |
| [R4] ROS 2 Actions | 长动作有 goal/feedback/result 和取消状态 | 承载 C3；语义事件、物理停止确认和所有权是本项目需补的应用契约 |
| [R5] MoveIt Servo | 提供连续运动及碰撞/奇异性/关节限制相关处理 | 可复用执行能力；不是视觉识别器或抓取成功证明 |
| [R6] MoveIt Task Constructor | 可组合规划阶段并传递几何状态 | 借鉴观察与接近的联合可行性；不预先承诺新依赖或将任务恢复写成固定图 |

备选取舍：

- 保留复合 pick 并加强内部主动观察：技术上可行，也可提供完整阶段反馈；但本项目选择把
  改变观察策略交回任务模型，便于研究能力组合。不能据此断言复合技能本身不合理或一定不可解释。
- 把每个视觉/控制阶段暴露给 reasoner：可见性强，但模型进入控制程序、增加延迟；不选。
- 完整主动抓取系统或新策略训练：可能有更强感知，但改变项目成本和论文范围；本轮不选。
- 本提案：操作级组合 + 证据契约 + 持续局部控制。新增的科学关注是决策边界和状态可信性，
  不是把常见视觉伺服、affordance 或 ROS action 当作算法创新。

## 9. 评审后实施前的验证计划

优先复用既有日志、图像、标定、机器人模型和 oracle 轨迹；不为理解问题而重复跑完整 Mission B。
Oracle 可说明几何/控制在给定条件下可行，但它使用的信息不能流入自主能力；旧钩取与新颈部夹取不能混作同一策略。

| 契约 | 首先做的离线检查 | 以后最小物理验证 |
|---|---|---|
| C1 | 标注已有视图中接触部位/遮挡；RGB-D/TF 同步与手眼投影；观测位和接近段可达性；不同物体/姿态的请求复用 | 到达一个由证据求得的视角，分项检查观察结果 |
| C2 | 同一目标序列回放；深度缺失、关联切换、夹爪遮挡的测量/预测区分；控制方向与姿态连续性 | 一个完整接近/抓取，记录真实误差、锁定连续性和保持证据 |
| C3 | 事件回放与可控执行替身验证停止、异常和取消；旧 worker 不再发令，旧反馈不覆盖新状态 | 一次关键停止/交接，确认持物时不会自动开爪 |

r2 增加跨契约检查：观察成功但抓取无解；同一身份的深度退化后恢复；已夹持却返回失败；
取消与保持控制交接；未收到进展消息但收到最终结果。逐项检查事实不被误提升、目标不被静默替换、
控制者不重叠，也不因终止而失去必要保持。它们是常规操作边界，不扩展成通用分布式容错框架。

这些是需回答的问题，不是预先声称能通过的固定数值门槛。所有容限须先列来源与测量方法。
首轮实施前必须确认：现有深度能否分辨接触部位；camera/tool 标定误差是否适配间隙；
末段遮挡如何处理；现有执行器能否确认停止并保留夹爪保持；环境几何是否覆盖手指通道。
缺项先做静态/离线证据分析，不能以 arbitrary 默认值“闭合”契约。

设计评审通过后，依赖顺序为：明确共享契约及停止交接 → 观察能力 → 锁定与伺服 →
持物核实与任务上下文 → 有针对性的开发运行。每步先复用现有模块，避免新增平行基础设施。
开发中的人工修复/快照恢复不计为正式自主成功；能力与知识冻结后再进入原有两项科学实验。

## 10. r2 自审发现与修正

| 问题 | 修正 | 纸面检查案例 |
|---|---|---|
| C1 要求路径可行、C2 又依赖 C1，存在循环 | 观察满足所需可见/可测条件即可；具体抓取可行性在锁定前判定 | 清楚看见但手臂无法接近：观察成功、pick 报 grasp_infeasible |
| 自由文本缺少可执行语义边界 | 使用注册表支持的部位/关系；未知请求明确不支持 | 无法解释的观察要求不会退化成固定姿态 |
| 先退出 worker 再保持，可能丢掉保持命令源 | 共享层先接管停止/保持再撤销旧发令权；物理反馈确认 | 夹着物体取消：旧 worker 停止，夹爪仍保持 |
| 把安全/FDIR 的存在当作已知 | 改成实施前必须核查的具体控制路径 | stop_unconfirmed 不释放冲突动作权限 |
| pick 成功后置条件及 failed 的物理效果含糊 | 定义脱离支撑和静止保持；持物与运输姿态分开；所有相关终态核实 | 已夹住但后续失败：保留持物证据，不自动重抓开爪 |
| 临时退化与真正换目标未区分 | 同一身份内可恢复测量；invalid 必须新建锁定 | 一帧深度缺失不会必然启动新一次抓取 |
| 共享 VLM、验证动作和反馈完整性边界不清 | 明确基线共享感知；验证不暗含动作；结果补齐阶段摘要 | 未收到进展事件仍可核对结果和证据 |

## 11. 修订后的纸面审查结论

修正上述问题后，未发现当前抽象层级上尚未处理的契约循环或控制权矛盾；与成熟的 affordance、主动观察、视觉伺服和
异步 action 思路相容。它不依赖 Mission B 专属坐标、固定扫描角度或模型级控制微步骤。
文献支持的是组成思想，不提供对本实现的成功保证。传感器可观测性、末段遮挡、接触验证和
物理停止确认仍是明确的实证义务；完成这些之前不能宣称已经具备可靠抓取或端到端能力。
